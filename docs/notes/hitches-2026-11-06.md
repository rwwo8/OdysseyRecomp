# Hitches in steady play (update 38, 2026-11-06)

## Problem

The user: "the game is very good, but there are strange drops, not many". Their log (`build/OdysseyRecomp.log`, a
two-minute session): Internal resolution Dynamic, frame interpolation on, SMAA, a window on a 165 Hz display.

## Evidence

1. Seven `[dynres]` changes in 110 s (1.00 -> 0.95 -> 1.00 -> 0.90 -> 0.95 -> 1.00 -> 0.95 -> 1.00), each right after a
   stall: a first-time shader build (`compile 57, link 110`), a scene start, a movie opening. On Vulkan there is no
   GPU timer (`gpu -1.0 ms`), so the frame time decided alone, and one slow frame lifted the half-second average over
   17.4 ms. Each change makes the render targets again: a hitch of its own, and the picture visibly softens and
   sharpens.
2. A hidden walk with the user's settings (`tools/hidden_run.sh`, 170 s, the camera turning): with no shader build,
   every 30 s one frame of 24-28 ms (t=65, 95, 125, 155) against 17-18 ms otherwise. With `ODYSSEY_NO_AUTOSAVE=1` (no
   pipeline cache save) it stayed (24 ms at the same times), so not the cache. The other 30 s job on the presenting
   thread: `vk_prepare_poll` -> `prepare_list_write`, which `stat`s each program's pipeline binary file (thousands).
3. Frame interpolation in a window on 165 Hz: 120 images a second on 165 refreshes can't be even (not measurable in a
   hidden run; the window has no display rate there).

## Cause and fix

1. `runtime/nvn/output_scale.c`: Dynamic lowers the resolution only when most frames of the half second are late
   (60 % over 18 ms and the average over 17.4 ms), not when one stall lifts the average.
2. `runtime/nvn/vulkan/exec.c`: the prepare list is written on a thread of its own (the exit's write waits for it).
3. Frame interpolation's description says it's for 120 / 240 Hz and that 144 / 165 Hz can't be even; the Video tab's new
   "Fullscreen refresh rate" keeps the 60 Hz mode by default.

## Verified

Same walk, same settings: `[dynres]` changes 7 (the user's log) -> 0 (`build/d1.log`, including the level load);
after the load every 2 s window's slowest frame 17-20 ms for 100 s with no 30 s spikes (`build/d3.log`), against
24-28 ms every 30 s before (`build/d1.log`, `build/d2.log`).

Not verified: the user's own display (165 Hz, windowed, interpolation on). Left: the first time an area loads, its
shaders are built (a few hundred ms once, cached afterwards).
