# Launcher and the game's logo (update 37, 2026-11-05)

## Problem

1. The user started `build/OdysseyRecomp.exe` after update 36 and got the setup page with "The game code builder is
   missing. Download Odyssey Recomp again ... (the zig and odysseygen folders)."
2. The start screen and the menu still had the old base's look (its red crescent). The user asked for a launcher of
   our own, with the game's logo, for a GitHub release.

## Evidence

- `build/OdysseyRecomp.log`: `[setup] data root ..., game files extracted` then `[setup] failed: The game code builder is
  missing`.
- `build/odyssey_game.dll.id` was `93fc548727b32ca9`; the exe (copied from `build-test/`) expects the current
  `GAMELIB_ID`, `a5c6e93f320e178d` (`make -p | grep ^GAMELIB_ID`). `build/` also had no `OdysseyRecomp.dll.a` (only the
  old import library).
- The logo: `romfs/LayoutData/TitleLogoParts.szs` (Yaz0) -> `layout.lyarc` (SARC) -> `timg/__Combined.bntx` -> one
  texture `CmTitleLogo^w`, 760x470, format `0x2d06` (ASTC 4x4 sRGB), block height 2^4 GOBs, one mip.
  `TitleLogoSmallParts.szs` has a 240x150 copy.

## Cause

1. Update 36 copied only the exe into `build/`. With the game code for another id, `gamelib_present` is false, so the
   setup page runs to rebuild it. In a source checkout the builder needs `build/OdysseyRecomp.dll.a`, which wasn't there,
   so `find_tools` failed and the page showed the release-player's message.
2. The look came with the move to the new base (update 35).

## Fix

- `tools/install_test_build.sh` copies the exe, `odyssey_game.dll`, its `.id` and the import library together, and
  refuses while the game runs. In a source checkout the setup page now says to run `make` instead of "download again".
- `runtime/game_logo.c`: reads the logo from the player's files at run time (romfs.bin, or the loose romfs folder) with
  the runtime's own Yaz0 / SARC reader, Tegra unswizzle and ASTC decoder, crops it, and fills see-through texels with
  their neighbours' colour (no dark fringe when scaled). Nothing of Nintendo's is in the repository.
- `runtime/ui/launcher.mm`: the start screen after setup. Logo over four tiles (Play, Settings, Controls, Files), a
  teal night sky. Settings and Controls open the menu's own pages in a panel. The logo also becomes the window icon and
  replaces the crescent in the in-game menu header. The setup page uses the same sky and lettering.
- The logo's texture is made only on the launcher's own frames (`vk_imgui_texture_rgba` records into the pending
  submission's upload buffer, which the game's threads also use while it runs).

## Verified (hidden runs, `ODYSSEY_NO_USER_INPUT=1`)

- `ODYSSEY_LAUNCHER=1 ODYSSEY_LAUNCHER_SHOT=90`: the launcher at 1920x1080 and 1600x900 with the logo.
- `ODYSSEY_LAUNCHER_PANEL=0` / `8`: the Settings and Controls panels.
- `ODYSSEY_LAUNCHER_PLAY=40 ODYSSEY_REBOOT_AT=500 ODYSSEY_MENU_AT=1300 ODYSSEY_WINDOW_SHOT=1360`: the game boots after
  Play (60 fps), restarts in place, and the in-game menu still shows the logo afterwards.
- `ODYSSEY_SETUP_SHOT` with a folder without game files: the setup page with the new look.

Not verified: the window icon (hidden windows have no taskbar entry), the launcher on a real controller and mouse
(only the scripted Play), macOS (no logo there: the texture helper is Vulkan only, so it shows the name).
